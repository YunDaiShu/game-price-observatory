# 游戏价格雷达 · game-price-radar

> 每天自动抓取游戏平台的**官方公开接口**，生成当日折扣/价格表与静态页，用来做「史低情报」类内容。
> **零 API key、零依赖、单源失效不影响整站。**

- 🌐 在线页面：<https://yundaishu.github.io/game-price-radar/>
- 📄 数据快照：[`data/latest.json`](data/latest.json)（历史快照在 [`data/history/`](data/history)）
- ⚖️ 许可证：MIT

---

## 这是什么

一个**只做一件事**的小工具：定时把各家商店的公开价格抓下来，整理成一张能直接看的表，并留档成按日快照。

它面向的场景很具体——**做游戏内容的人每天都要回答"今天哪款值得买"**，而这个问题的原料就是价格与折扣。手工抄太慢，抓取脚本又容易因为站点改版就废掉，所以这里按"每个源一个文件、单源失败不影响整站"的方式组织。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 当前特惠榜 | 自动拉取 Steam 当期折扣列表，不需要你维护名单 |
| 指定游戏监控 | 在 `data/watchlist.json` 里填 appid / 关键词即可 |
| 按日留档 | 每次运行写一份 `data/history/YYYY-MM-DD.json`，可用于画历史价格曲线 |
| 失败可见 | 抓不到的源会写进 `errors`，并在页面底部标红，不会静默失败 |
| 零依赖运行 | 只用 Node 内置 `fetch`，`node src/index.mjs` 即可 |

## 数据来源与合规

| 源 | 用途 | 状态 |
|---|---|---|
| Steam `appdetails` | 指定游戏当前价 / 原价 / 折扣 | ✅ 可用 |
| Steam `featuredcategories` | 当期特惠列表 | ✅ 可用 |
| Apple `iTunes Search` | 付费手游当前售价 | ⚠️ 仅对付费游戏有意义（免费游戏无折扣概念） |
| TapTap | — | ❌ 不抓取：无公开接口，且属于他人平台整理数据 |
| 主机（PlayStation / Xbox / Switch） | — | ❌ 暂不抓：无公开合法接口，或服务条款不明确 |

**原则**

1. 只使用**公开、无需登录**的接口；
2. 只保存**名称、价格、折扣、时间戳**这类事实数据，**不保存**简介、图片、评测正文等版权内容；
3. 遵守对方 `robots.txt` 与调用频率，不做高频轮询，不绕过任何访问限制；
4. 若确认某源已禁止抓取，**直接移除该源**，不做规避。

## 快速开始

```bash
node src/index.mjs
```

产物：

| 路径 | 内容 |
|---|---|
| `data/latest.json` | 最新一次结果（含 `errors`） |
| `data/history/YYYY-MM-DD.json` | 按日快照 |
| `docs/index.html` | 自包含静态页（无框架、无 CDN，可直接托管） |

## 目录结构

```text
game-price-radar/
├─ src/
│  ├─ index.mjs                 主流程：抓取 → 去重 → 排序 → 输出
│  └─ fetchers/                 每个数据源一个文件
│     ├─ steam.mjs              指定游戏价格
│     ├─ steam-specials.mjs     当期特惠列表
│     └─ appstore.mjs           App Store 公开接口
├─ data/
│  ├─ watchlist.json            监控名单（可自行修改）
│  ├─ latest.json               最新结果
│  └─ history/                  按日快照
├─ docs/
│  ├─ index.html                生成的静态页（GitHub Pages 发布目录）
│  └─ ADD-A-SOURCE.md           怎么新增一个平台的抓取源
└─ .github/workflows/daily.yml  每日定时任务
```

## 自动化

- 每天 **UTC 00:10（北京 08:10）** 自动运行一次，也可在 Actions 页面手动触发；
- 运行完成后自动提交 `data/` 与 `docs/index.html`，页面随之更新；
- **运行失败会自动开一个 issue**，标题带日期，正文带日志链接。

## 监控名单

编辑 `data/watchlist.json`：

```json
{
  "steam": [730, 1245620, 1086940],
  "appstore": ["原神", "星露谷物语"]
}
```

- `steam`：填 Steam appid（商店链接里那串数字）；
- `appstore`：填搜索关键词，取第一条结果。

## 怎么新增数据源

见 [`docs/ADD-A-SOURCE.md`](docs/ADD-A-SOURCE.md)：写一个 `fetcher`、接进主流程、跑一次验证，三步。

## 设计原则

1. **多源降级**：任一源失败，其余照常输出，失败项写入 `errors`；
2. **可维护优先于聪明**：每个源独立文件，改版时只改那一个；
3. **零密钥**：全公开接口，clone 下来直接能跑；
4. **静态优先**：页面是自包含 HTML，不依赖框架、不依赖 CDN，五年后仍能打开；
5. **只存事实**：价格会变，本仓库只记录**抓取时刻**的数据。
